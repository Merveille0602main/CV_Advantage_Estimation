# 数据契约 v1

一条 Episode 只含一条连续轨迹。数组首维都是 transition 顺序，保存为普通数值数组，禁止 pickle。

| 字段 | 内容 | 约束 |
| --- | --- | --- |
| episode_id | 全局唯一轨迹标识 | 非空，建议带数据源与版本前缀 |
| parent_id | 原始轨迹或共享初始化的家族 | 全家族进入同一 split |
| task_id | 唯一任务 | 当前学习器一次只训练一个任务 |
| policy_id | 固定策略及随机机制版本 | 不能把随意混合策略当同一策略 |
| obs / next_obs | 执行动作前后的低维状态或固定特征 | 数值矩阵、同形状、有限值、时序连续 |
| action | 当次实际执行的动作 | 数值矩阵；动作单位与范围记入 metadata |
| reward | 该动作执行后产生的原始奖励 | 不能用整条轨迹 success 填充每一步 |
| terminated | 真正任务终止，包括定义内的任务时限 | 布尔向量，只允许最后一步为真 |
| truncated | 因采集/存储中断而截断 | 布尔向量；末尾 next_obs 必须真实存在 |
| remaining_steps | 执行当前动作前剩余控制步数 | 正整数，每步递减；属于 V 的输入 |
| metadata | 来源、奖励版本、动作单位、随机种子、特征版本、成功状态等 | 只作审计，不默认送入模型 |

时间索引由数组下标确定；RLinf 原 frame_index 必须从零开始连续，缺帧或重复直接报错。
家族标识未知时暂以 episode 为家族，必须在报告注明限制。正式冻结前核查共享初始化与派生轨迹。
当前 split 为按家族随机划分；未实现成功率分层，极小数据可能产生空 split，不能直接进入训练。

## RLinf / LeRobot 映射

- 数据表：默认 `data/**/*.parquet`，支持轨迹跨文件；按 episode/frame 显式整理。
- 观测：配置 `state_columns` 可拼接多个低维列。
- 奖励：显式配置 `reward_column`；可从 `reward_sidecar` 按轨迹与帧索引一对一合并。
- 现有 `return`、`advantage`、质量标签不读取，不作为当前 V 训练监督。
- 终止：优先提供 `terminal_column` 和 `truncated_column`。若无终止字段，只能在核实每条轨迹均完整结束后明确声明 `episode_end_is_terminal`。
- 无独立 next_obs 时，仅对完整 terminal 轨迹按下一帧构造；最后一帧填掩码占位，永不用于 bootstrap，不代表真实末态。
- 非完整轨迹必须配置 `next_state_columns`，拒绝伪造末尾状态。
- 必须明确 `rows_are_primitive_transitions`；动作 chunk、视频帧和控制 step 不能混为一个时间单位。
- `task_horizon` 是任务定义内的时限，不是这条轨迹的实际长度。提前成功的轨迹不能用自身长度充当剩余时长。

导入器按文件读取选定列，不读取视频；当前会在内存中汇集这些列以处理跨文件轨迹。大规模数据应分源分批转换，后续再扩展流式存储。

## 数据到达后的验收

1. 记录数据集链接、版本、策略来源和任务。
2. 检查 schema，确认不是 assets 或仅模型权重。
3. 核实 reward、动作、观测的前后对齐，以及末尾行是否真是一次已执行动作。
4. 确认动作粒度、剩余时长、终止与截断定义。
5. 抽查成功和失败轨迹；确认 parent_id，冻结映射、哈希与 split。
6. 用少量轨迹完成一次更新，再扩大规模。真实数据未到前，人工格式测试不能代替上述验收。
